# Встреча хранит снимок Типа встречи

Встреча могла бы ссылаться на Тип встречи только по идентификатору и брать название и продолжительность из него при каждом чтении. Вместо этого Встреча хранит собственный отрезок времени `start`–`end` и название Типа встречи на момент записи, а `meetingTypeId` остаётся лишь ссылкой для фильтрации. Так правка Типа не переписывает уже сделанные записи, Тип можно удалять без проверки предстоящих Встреч, а правило занятости работает на интервалах самих Встреч, не обращаясь к Типу.

## Consequences

- `meetingTypeId` у Встречи может указывать на удалённый Тип: списки Встреч не должны его разыменовывать.
- Удаление Типа встречи не возвращает конфликт из-за предстоящих Встреч.

Решение принято в тикете карты [Сущности контракта: Тип встречи, Слот, Встреча](https://github.com/alexander-lis/ai-for-developers-project-386/issues/4).
