# Встречи хранятся в SQLite, пересечения исключает немедленная транзакция

Прототипу хватило бы хранения в памяти процесса, а настоящая база вроде PostgreSQL дала бы ограничение-исключение на пересечение интервалов. Выбрали середину: SQLite-файл через EF Core с миграциями, чтобы данные переживали перезапуск сервера без отдельного контейнера. Уникальный индекс пересечение отрезков времени не выражает, поэтому создание Встречи идёт в одной немедленной транзакции (`BEGIN IMMEDIATE`, поведение `Microsoft.Data.Sqlite` по умолчанию): проверить, что Тип встречи существует и Слот свободен, вставить Встречу, зафиксировать. SQLite пропускает только одного пишущего, так что второй одновременный запрос увидит первую Встречу и получит конфликт. Замок в приложении отвергли: он работает лишь внутри одного процесса и повторяет то, что база уже гарантирует.

## Consequences

- Проверку пересечений нельзя выносить из транзакции, иначе гонка вернётся; её ловит API-тест с параллельными запросами на один Слот.
- Время Встреч хранится как `DateTime` в UTC: `DateTimeOffset` в SQLite не сравнивается в SQL. Общий конвертер помечает прочитанные значения как UTC.
- У Встречи нет внешнего ключа на Тип встречи: по ADR 0001 удаление Типа Встречу не трогает.
- Переход на PostgreSQL потребует новых миграций и, вероятно, замены транзакции на ограничение-исключение.

Решение принято в тикете карты [Хранение данных и одновременные записи](https://github.com/alexander-lis/ai-for-developers-project-386/issues/6).
